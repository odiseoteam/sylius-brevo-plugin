# Contributing

Issues and pull requests are welcome at
[odiseoteam/sylius-brevo-plugin](https://github.com/odiseoteam/sylius-brevo-plugin).

## The test application

The plugin is developed against a real Sylius application: `tests/TestApplication`, running on top of
`sylius/test-application`. Everything runs in Docker, no PHP needed on the host.

```bash
make init            # Containers, composer install, frontend build
make up / make down  # Start / stop
make php-shell       # A shell in the PHP container
make database-init   # Create the database and run migrations
make load-fixtures   # Sylius fixtures
```

The shop is then at `http://localhost:8090` and the admin at `http://localhost:8090/admin`, with
`sylius` / `sylius`.

> The `nginx` service binds port 8090. If that port is taken, change it in `compose.override.yml`,
> generated by `make init` from `compose.override.dist.yml`, and not tracked by git.

To try it against a real Brevo account, add a configuration for the channel in **Brevo > Configuration**
with the API key of a test account. Tests never use it.

## Running the checks

```bash
make phpunit         # PHPUnit: unit, functional and integration suites
make behat           # Behat
make phpstan         # PHPStan, level max
make ecs             # Coding standard
make deptrac         # Layer dependencies
make composer-unused # Unused and shadow Composer dependencies
```

PHPUnit suites can be run one at a time with `--testsuite unit` (`functional`, `integration`,
`non-unit`, `all`).

Tests never reach Brevo: in the test application the HTTP transport is
`Odiseo\SyliusBrevoPlugin\Testing\FakeBrevoHttpClient`, which records requests and answers what each
test queues. It keeps its state in a file, so Behat contexts and the browser kernel share it.

### The fresh install

CI installs the plugin on a clean Sylius-Standard with the Flex recipe kept in `recipe/` (the source of
the `symfony/recipes-contrib` one: update both together when the install steps change). Run the same
locally, against any empty database:

```bash
DATABASE_URL=mysql://root@127.0.0.1/brevo_install .github/scripts/fresh-install.sh /tmp/brevo-install
```

## The documentation

The docs site, for this plugin and Brevo Pro, lives in `docs/` (VitePress):

```bash
cd docs
npm install
npm run docs:dev     # http://localhost:5173
npm run docs:build   # also fails on dead links
```

Screenshots go in `docs/public/images/`, taken from the test application at 1280×800 with a device
scale of 1.25 (1600×1000), in the light theme and without the Symfony toolbar.

## What CI enforces

Every pull request runs the matrix, Sylius 2.0 / 2.1 / 2.2 / 2.3 × PHP 8.2-8.4 × Symfony 6.4 / 7.4 on
MySQL 8.4, plus a PostgreSQL job and the fresh install. Each job validates `composer.json` and the
container, and runs PHPStan, ECS, Deptrac, the Composer dependency analyser, PHPUnit and Behat.

## Conventions

- **BDD first.** Observable behavior starts as a red Behat scenario; mechanics get PHPUnit tests.
- **Never call Brevo from a request.** Implement `BrevoMessageInterface`, send it with
  `BrevoMessageDispatcherInterface` and handle it on `odiseo_brevo.bus`. The admin "Test connection"
  is the only exception.
- **Never send from inside a flush.** Collect entity changes in Doctrine `onFlush` and dispatch them
  in `postFlush`, like `Contact\EventListener\CustomerChangesListener`.
- **A Brevo failure never breaks a shop request or a checkout.**
- Every Brevo call goes through a `Client\Api\*ApiInterface`, with the credentials passed per call.
- Payload values go through the helpers: `MoneyFormatter`, `DateFormatter`, `PhoneNumberNormalizer`,
  `ChannelUrlGenerator` (never the request host).
- Services, routes, parameters and translations are prefixed `odiseo_brevo.`.
- Comments explain **why**, not what. If the code already says it, don't repeat it.
- Translation keys are added in every locale of `translations/`.
- Every pull request updates the docs and `CHANGELOG.md` with what it adds.
